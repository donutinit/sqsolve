## Finding while updating

The first start of the candidate on mininas stopped in a loop with `SQS-C010 permissions too
open on a secrets file: master.key has mode 700`. The three datasets of the test installation
were NFSv4 datasets with inherited ACL entries (`group:builtin_users` with full access on every
file), so the secrets were readable by other local users, `chmod` could not narrow them, and
`sqsolve-init` still printed `done`. Fixed in this release: `sqsolve-init` now checks the mode it
gets and stops with `SQS-C085` (`docs/12-deployment.md`, "Permissions and ACLs"). On mininas the
ACLs were stripped from the three datasets, as that section describes, and the app started.

Run with a script against the panel, the console in the container and PostgreSQL over TCP; 28
of 28 checks passed:

| Area | Checks |
|---|---|
| Upgrade | The update from 1.1.2 migrated SQLite and kept the catalog; `sqsolve doctor` without failures; no `backup.path_invalid` event at startup |
| Library life | A library created from the panel, initialized from the workstation as Resolve does (database and tables over TCP), active on its own |
| Backups | Two backups from the panel; download of a `pg_dump` archive; deletion of the older one; `sqsolve catalog rebuild --wait` |
| Sessions | Changing the password closed the user's other session and kept the one that changed it |
| Interruption | The container restarted in the middle of a backup: the job ended interrupted or finished, never running, and no `.partial` file was left |
| Recovery | The database dropped by hand as the superuser: at the next start reconciliation reported the library missing; "Recreate from the latest backup" brought back its rows with the same password |
| Destructive | Delete to the trash and purge: the library is purged, its role no longer logs in, its backups are kept |
| Audit | `sqsolve audit verify`: the chain is intact |

An unplanned power cut hit mininas and the workstation during the exercise, while sqsolve was
idle: both came back on their own, `sqsolve doctor` reported every check `ok` and the audit chain
was intact.
